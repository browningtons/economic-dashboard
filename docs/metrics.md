# Metrics

The handful of numbers that matter for the Economic Dashboard.

Seeded 2026-07-24 by Launch Shield (first-wolf bootstrap). **This is a skeleton
that reflects reality, not an aspiration** — most of the product-analytics rows
below are deliberately empty because nothing is wired.

## Current state: no product analytics

There is no analytics integration in this repo. Grepping `src/`, `api/`, and
`index.html` for `analytics`, `gtag`, `plausible`, and `posthog` returns nothing.
The site is a static GitHub Pages deployment, so the only ambient data is
whatever GitHub Pages traffic reporting gives, at repo level.

That is a defensible choice for a public example dashboard with no funnel and no
money — **do not add an analytics dependency without Paul asking for it.** The
useful metrics here are pipeline-health metrics, and those already exist.

## Pipeline health (already instrumented)

Source of truth: `public/data/data_status.json`, regenerated by
`npm run validate:data`. This is the honest, high-value metric set for this app,
and it is already computed — it just needs to be *watched*.

| Question | Field | Healthy value | Action when it breaks |
|---|---|---|---|
| Did the last validation pass? | `status` | `PASS` | Read `failures[]`; see the auto-filed "Data validation alert" issue. |
| **Is the pipeline still running at all?** | `generatedAt` | within ~4 days | **This is the one that failed.** 21 days stale as of 2026-07-24 — see R1. Nothing watches it today; backlog task 2 adds the check. |
| How many series are broken? | `failedSeriesCount` / `totalSeriesCount` | `0` / `27` | Investigate the named series against FRED. |
| Are any series silently forward-filled? | `series[].forwardFill` | `0` | A growing forward-fill count means the source stopped publishing. |
| Is a series lagging its release window? | `series[].releaseWindowStatus` | `PASS` | Check the FRED release calendar for that series. |
| Is the headline Buffett ratio computable? | `latestBuffettRatio` | non-`null` | `null` means the market-cap override or the `NCBCEL` fallback failed. |

**Reading the table above on 2026-07-24:** `status: PASS`, `failureCount: 0`,
`latestBuffettRatio: null`, `generatedAt: 2026-07-03`. Five of six rows look
healthy. The file is three weeks old and the sixth row is the only one that says
so. That asymmetry is the entire lesson — see the operating loop's "a green
heartbeat is not evidence of a working system."

## Principles

- Track only what someone will act on.
- Prefer freshness and correctness metrics over traffic counts — this app's
  product *is* the accuracy of the number.
- A metric that can read healthy while its purpose goes unmet is worse than no
  metric. Every check added here must have a defined answer to "what does this
  say on the day it stops working?"
